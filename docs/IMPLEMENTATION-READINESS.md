# Implementation Readiness

[Portfolio home](../README.md) · [Projects index](../PROJECTS.md) · [Delivery proof](DELIVERY-PROOF.md)

A workflow is ready to progress beyond a prototype when its business purpose, data boundaries, technical dependencies, and operating responsibilities are explicit.

## Readiness checks

- [ ] Scope, outcome, and acceptance criteria agreed
- [ ] Process owners, approvers, and escalation contacts assigned
- [ ] Triggers, inputs, outputs, state, and exceptions documented
- [ ] Realistic schemas and representative test data reviewed
- [ ] Credentials and permissions use least-privilege access
- [ ] Sensitive data, retention, and compliance boundaries reviewed
- [ ] Retry, timeout, duplicate, rate-limit, and failure behavior tested
- [ ] Logging, monitoring, rollback, and support runbook available
- [ ] Known limitations and unresolved risks recorded

## Evidence standard

A JSON export, screenshot, or successful demo alone does not establish production readiness. Promotion requires documented validation, operational ownership, and an agreed response to failure cases.
